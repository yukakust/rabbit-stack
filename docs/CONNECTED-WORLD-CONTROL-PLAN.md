# Управление миром: путь к повседневной версии

Цель: пользователь описывает желаемый результат текстом или голосом; система
создаёт либо меняет мир, детерминированно проверяет кандидат, подписывает пакет,
передаёт по Bluetooth и подтверждает применение на Dell. Пользователь не копирует
команды. LLM предлагает изменения, но не принимает решения о допустимости пакета.

## Что уже делает единый контроллер

`experiments/x86-64-uefi-connected-supervisor-v1/ask_connected_world.py`:

- Привязывает предложение к текущему миру, проверяет V3 данные, подпись и реальный
  C runtime на хосте; сохраняет точный пакет и сессию до передачи.
- Перед продолжением читает состояние Dell. Точная квитанция уже применённого
  пакета завершает операцию без повторной передачи данных.
- Сохраняет подтверждённый объём между запусками, включая частичные логи.
  Повторный запуск не начинает передачу заново при обнаружении потери данных.
- Передаёт сохранённый минимум непосредственно Mac sender: сброс между чтением
  состояния и BEGIN также блокирует DATA/COMMIT при регрессии объёма.
- Делает не более двух попыток за вызов, сохраняет неизвестный результат,
  отличает отклонение и ожидающее применение, не затирает чужую активную сессию.
- Наследует блокировку состояния в дочерние отправители: при остановке
  контроллера ещё работающий sender не допускает второго контроллера.
- Показывает текущий мир и незавершённую операцию через `--status` (JSON).
  `--status --query` добавляет чтение состояния Dell без изменения сцены или
  продвижения локального состояния. Логи сохраняются отдельно от JSON.

При регрессии полученных данных нужен разбор состояния приёмника. Автоматическая
перезагрузка, новая сессия или новый счётчик не используются как скрытое исправление.
Хостовые проверки и искусственные сбои не считаются физическими испытаниями радио.

## Ближайшее продолжение

1. Свести выбор изменений в планировщик с явными маршрутами: имеющиеся данные,
   новые assets, недостающая возможность движка. Сейчас artwork создаёт агент,
   а неподдерживаемые изменения малый LLM proposer отклоняет. Автоматического
   создания/подписания нового native движка в этом контроллере нет.
2. Добавить журнал запросов и версий поверх контроллера; восстановление старого
   мира должно быть новым проверенным пакетом с возрастающим счётчиком.
3. Проверить контролируемые физические обрывы и длительную серию передач, отдельно
   сохраняя baseline и причину каждого отказа. Ранее pacing помог, но не доказывает
   устранение первопричины.
4. Подключить голос, затем каталог переиспользуемых компонентов к этим маршрутам.

## Границы текущей системы

Активный мир — кот в красной шапке, worldcounter3. Nativecounter3 отдельно уже
израсходован отклонённым trial; следующая новая native версия требует counter>=4
и привязки к актуальному подписанному миру. Миры пока подписываются установленным
публичным development Creator, а native релизы — отдельным ключом владельца.
Квитанция коррелирует пакет/сессию/счётчик, но не является аутентифицированной
аттестацией устройства или независимым наблюдением экрана.

Миры и совместимые движки обновляются беспроводно. Изменение неизменяемого bootstrap
требует отдельного решения. RAM-состояние Dell само по себе не переживает перезапуск.
