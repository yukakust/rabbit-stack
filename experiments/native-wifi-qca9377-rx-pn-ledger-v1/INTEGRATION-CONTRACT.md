# Owned CCMP counter metadata; not authenticated delivery

This software-only slice accepts the QCA9377 PCI qca988x descriptor-v1 single-MSDU raw profile and exact HTT op3/version3.56 INORD messages. Caller must already hold the real QRxOwner OWNED mapping under the source-bound SERVICE_READY full-reorder service65 contract. No version number grants that service. All callbacks complete before buffer refill; callers pass a coherent copied 2048-byte descriptor/frame after DMA acquire. This module neither dereferences a physical address nor changes ring ownership.

The frozen data-path producer quarantines encrypted, Protected, non-NONE7, ENCRYPT_REQUIRED or crypto-error frames and quiesces radio work. That policy remains required. A QPN_COUNTER_ACCEPTED result advances a CPU **metadata** model only; it does not authenticate a packet, release quarantine, open the controlled port, or authorize plaintext/IP delivery. Native integration must stage the candidate PN and commit the security PN only after a genuinely source-backed CCMP MIC/decryption result. An arbitrary callback success or firmware PN_VALIDATED Boolean is insufficient. This component is deliberately not that authenticated commit API.

The primary Linux commit is 6b5a2b7d9bc156e505f09e698d85d6a1547c1206. `net/mac80211/key.c` seeds all 17 CCMP queues from the six-byte little-endian initial sequence; `wpa.c` converts the IV to big-endian PN, rejects lower/equal sequence, verifies MIC when hardware has not authenticated, and only then updates the accepted PN. The exact upstream `ccmp_hdr2pn` and ath10k HL 48-bit comparator bodies are compiled as independent test oracles. The HL comparator provides arithmetic evidence, not authority for the QCA9377 low-latency DMA path. Full-reorder INORD flags are not PN validation. The low-latency IV-stripped/decrypted shortcut in mac80211 requires its actual hardware contract; it cannot be copied as an unchecked input flag here.

First PTK index0 accepts absent or exact six-byte initial RSC; first GTK index1..3 requires exactly six bytes and supports nonzero RSC. Only one install is pending. SEC_IND must be a real owned raw HTC pipe1 event0 message on the negotiated endpoint, newer than the posted floor, with exact peer/cipher6/unicast cast. SEC_IND contains no key index, so sole pending operation is necessary; ambiguous cast/peer/cipher quarantines. No duplicate SEC_IND resets PN and no index can be reinstalled. Rekey, key deletion, multi-peer/multi-link, fragmented MPDU, A-MSDU, decapped or IV-stripped frames remain unsupported.

The descriptor PN48 and actual CCMP IV must agree; key_id_octet must equal actual IV octet. Peer, BSSID/transmitter, unicast receiver or multicast GTK, sequence, TID/non-QoS queue16, encryption type6, epoch, map identity, completion and original INORD paddr/length are joined. Peer-invalid/timeout and ENCRYPT_REQUIRED are rejected in addition to original descriptor crypto/FCS/length errors. Unknown fw_desc is rejected conservatively, not interpreted as a crypto confirmation. Within one INORD completion several distinct owned paddr values may be processed; a paddr repeats at most once and PN strictly increases per key/TID. Older completions, lower/equal PN and replayed installation are rejected without output or metadata mutation.

No credentials or key bytes are read. Tests use public synthetic metadata and actual upstream source bodies. There is no physical success, association, target scan, firmware key-ACK-to-MIC proof, native candidate integration, or RF admission in this report.
