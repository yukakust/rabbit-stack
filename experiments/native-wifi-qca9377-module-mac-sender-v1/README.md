# Saved public module chunk sender

Mac Objective-C central discovers the new native module service only on the
exact saved cached peripheral. It reads current status before any write, resumes
the exact retained session offset, and requires an exact80-byte epoch/session/
length/digest/result status before declaring a chunk accepted. UUID/receipt is
not device attestation. No credential provisioning or signer is present.

Different retained sessions fail closed unless the current complete ACCEPTED
status is byte-for-byte the separately saved previous receipt for the reviewed
next chunk. No rejected/closed/staging session is automatically overwritten.
One shared state.lock serializes all physical controllers. Disconnect/timeout
keeps saved bytes and status; resume is the same session without re-signing.
The actual privileged parent still verifies the owner signature, target,
installed parent hash, epoch, counter, role/ABI and module lifecycle. Chunk
acceptance is not complete module loading, entropy approval or WiFi readiness.

Host compilation/preflight and Python wire-negative tests do not start a
Bluetooth manager. Actual callback fault tests, installed native service,
whole-candidate source/admission and physical delivery remain required before
this sender is enabled by a Root controller. No Bluetooth operation has run.
