# Owner AUTH / encrypted recipient ACK: offline component

This is a post-Noise-Split framing component, not a native identity or provisioning approval. Fixed suite is Noise_NK_25519_ChaChaPoly_SHA256, Mac initiator / Dell responder. Caller must provide genuine exclusively owned fresh Split ciphers, the actual final handshake hash and prologue hash, native/target/boot epoch context and already trusted owner Ed25519 public key. Physical recipient fingerprint/pinning, trustworthy device RNG, real EFI ownership/full-link and independent protocol review remain unimplemented by this component.

Ordinary Ed25519 from the unchanged Monocypher optional SHA512-Ed25519 verifier authenticates the owner; BLAKE2 EdDSA is never substituted. Actual unchanged Noise-C ciphertext encryption/decryption and Monocypher SHA512 implement transport and AUTH correlation; there is no custom crypto, KDF or handshake.

Wire is exactly304 bytes:24-byte authenticated associated-data header and280-byte ciphertext/tag. Header is RNOISE01, LE32(version1,type,direction,encrypted_length280). AUTH type/direction1 is Mac→Dell; ACK2 is Dell→Mac. Wrong role/type/direction/length/reserved/padding is rejected. Per-direction initial Noise nonce must be0; success consumes it to1. No retransmit/re-encrypt/reset mechanism is implemented.

AUTH plaintext264 bytes contains signed canonical200-byte message plus64-byte Ed25519 signature. Canonical fields: ROWN0001[8], LE32(version1,type1,direction1,reserved0), LE64(sequence0,epoch),32-byte final handshake hash, prologue hash, target digest, native digest, owner public key. Mac checks its provided signature before encrypting. Dell checks exact expected context plus the actual ordinary Ed25519 signature after decryption.

ACK plaintext264 bytes repeats the canonical context with type/direction2 and appends SHA512[64] of the entire accepted AUTH plaintext (including its signature). Mac requires exact ACK context and AUTH digest before the local credential-send predicate opens. Before ACK it stays closed. Any structurally valid receive attempt with failed AEAD/context/signature/digest aborts the component; caller must tear down the whole borrowed Noise session rather than retry/reset counters. Duplicate AUTH/ACK is rejected by phase/nonce. Duplicate ACK after a previously valid ACK does not create a new authorization. No actual credential processing exists here.

`oa_init` refuses replacement of an already bound session. The component allocates nothing and borrows ciphers; lifetime/resource release remains caller responsibility. Pointer overflow and buffer overlap checks run before operation, including the full pinned cipher allocation size (bounded512), not just its public base. This does not validate arbitrary pointer mappings. Canonical signing buffers and public hashes must have genuine caller provenance; an authorized trusted caller can otherwise lie about its context. The fixed pinned Noise-C internal ABI is used solely because its public API has no nonce getter; source hash and ABI dependence are explicit.

The current test corpus has no PUBLIC valid signature for this new200-byte canonical AUTH. It uses the real RFC8032 empty-message verification vector, actual Ed25519 rejection and actual Noise AEAD failures. A separately labelled SYNTHETIC pre-authenticated phase fixture tests real encrypted ACK success, every ciphertext/plaintext mutation, context/hash/direction/replay and the credential-send predicate. It does NOT prove an actual successful owner AUTH→ACK path. No fake verifier is linked and no signing/private fixture seed is loaded. A canonical PUBLIC signedAUTH fixture is still needed for that positive end-to-end proof.

All C/ASAN/UBSAN and component/verifier COFF compilation occur only on Yukabox in parallel-owner-auth-v1. No hardware, device RNG, real credentials, signer, key store, state, candidate, radio or native source changes occur. Monocypher4.0.3 and Noise-C cfe25410979a87391bb9ac8d4d4bef64e9f268c6 are unchanged and hash-bound. Existing mature source licensing remains in referenced files; local adapter files are original.
