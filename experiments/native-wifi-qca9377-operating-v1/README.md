# Native QCA9377 control trial candidate

This candidate extends the exact native42 boot path with real CE0 TX, CE1
endpoint-zero RX and CE2 WMI SERVICE_READY RX. It borrows the retained adapter,
registered coherent mappings and exact firmware pin after HTC READY. No extra
allocation, target address, firmware change or persistent storage write.

It posts RX before sending endpoint-zero connect-WMI/connect-HTT/setup commands.
The HTC endpoint id is CE metadata (zero for these commands), rather than BMI's
special0x3fff transfer id. Every hardware index/cookie/length is checked through
existing CE ownership code. One data buffer per direction; no duplicate DMA post.
An early endpoint-zero response is validated and deferred until TX completion.
One early WMI frame is copied independently until the assigned endpoint is known.
Only the validated SERVICE_READY ABI/memory/regulatory description is accepted.

The20-second diagnostic retains mappings/pin on success, failure, timeout or
unknown doorbell outcome. The actual outer native entrypoints then perform the
existing all-engine stop/BM-off/flush/unmap/free and only afterwards unpin. This
is not a persistent operational radio. No WMI INIT, host-memory allocation, scan,
credentials, association, encrypted traffic, DHCP/IP or WAN exchange.
